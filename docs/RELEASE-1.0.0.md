# jenny 1.0.0 release notes

## Overview

The first stable release of `jenny`, the Timefold Solver-based port of Bob Jenkins'
`jenny` covering-array generator. 1.0.0 integrates seven suite-minimization
optimizations ported from the [Jenny-go](https://github.com/chas678/Jenny-go) Go
port (PR [#15](https://github.com/chas678/jennyj/pull/15)), compounding to a
**verified-clean 100 ±1-row** covering array on the jenny self-test benchmark —
`hard==0`, 0 uncovered tuples, 0 without-violations — down from the honest 107-row
baseline and beating C jenny's 116 rows.

## Highlights

- **`-j<K>` best-of-K replicas** — run `K` independent solver replicas and keep the
  smallest valid suite.
- **Hand-rolled `IncrementalScoreCalculator`** — faster move evaluation than full
  rescoring, cross-checked against the declarative constraint provider under
  `FULL_ASSERT`.
- **Smaller suites** via a rewritten greedy initializer, deterministic Shrink/Recover
  custom phases, and a new `EvictRowMove` (rehome a row's uniquely-covered tuples via
  legal single-cell flips, then deactivate it).
- **Minimal-core reporting** for genuinely-uncoverable tuples (one line per
  infeasible core) and a bounded tuple-enumeration cap that fails cleanly instead of
  exhausting memory on pathological inputs.
- **Strict correctness gate**: `hardScore==0` (no uncovered tuple, no `-w`
  violation) end-to-end, independently verified against a fresh without-check and a
  full tuple-enumeration oracle — not just the in-suite score.

## Quality / benchmark numbers

On the jenny self-test (`-n3 4 4 3 3 3 3 3 3 4 3 3 4` + 13 `-w` restrictions):

| | rows | notes |
|---|---|---|
| C `jenny` | 116 | reference implementation |
| 0.1.0 honest baseline | 107 | pre-1.0 three-phase solver, `hardScore==0` verified |
| **1.0.0** | **100 ±1** | `-j1`=101, `-j8`=99, strict IT ×3 → 100/99/100 |

Verification: 74 unit + 9 integration tests green; an independent external
validator (fresh without-check + full 7,214-triple enumeration) confirms the
`-j1`=101 and `-j8`=99 results are genuinely valid, and
`IncrementalScoreParityIT` runs the real solver pipeline under `FULL_ASSERT` to
cross-check SP3's `EvictRowMove` and SP4's shrink/recover phases (0
score-corruptions, final `0hard`).

**Known caveat**: SP2's incremental scoring is ~4.5–6x faster in isolation but only
~1.3x end-to-end once `EvictRowMove`'s rehome-search cost is counted; SP3
(`EvictRowMove`) ties the row-count floor at full time budget on this problem (a
candidate for the acceptor/weight tuning follow-up).

## Install

See the [README Install section](../README.md#install) — Homebrew is the primary

## What's changed since 0.1.0

See [CHANGELOG.md](../CHANGELOG.md#100---2026-07-08) for the full list. In short:
0.1.0 was the first Homebrew-distributed release running the original three-phase
solver (107-row honest baseline); 1.0.0 keeps the same CLI surface and output
format and layers the seven optimizations above on top, with no breaking changes
to flags or output.

## Release checklist

This repo's release process is fully documented in
[docs/RELEASING.md](RELEASING.md); the steps specific to cutting 1.0.0:

1. [x] Merge PR [#15](https://github.com/chas678/jennyj/pull/15)
   (`spike/integration` → `main`).
2. [x] `CHANGELOG.md` — `[1.0.0] - 2026-07-08` section added, compare/tag links
   updated.
3. [x] `pom.xml` — `<version>` bumped `0.1.0` → `1.0.0`.
4. [x] Local verify — `mvn -o -DskipTests package` succeeds;
   `java -jar target/jenny.jar --version` prints `jenny 1.0.0`; `target/jenny.jar`
   filename is unaffected by the version bump (`<finalName>jenny</finalName>`).
5. [ ] For a real release, also run the quality oracle:
   `mvn verify -Dit.test=JennyBeatsBenchmarkIT`.
6. [ ] Commit and tag on `main` (after merge):
   ```bash
   git commit -am "Release v1.0.0"
   git tag v1.0.0
   git push && git push --tags
   ```
7. [ ] Pushing the tag triggers `.github/workflows/release.yml`, which builds the
   jar, verifies `--version` output matches the tag, creates the GitHub release
   with `target/jenny.jar` attached (release notes auto-generated by
   `softprops/action-gh-release`; this file can be pasted in as a manual
   supplement/override via `gh release edit v1.0.0 --notes-file docs/RELEASE-1.0.0.md`
   if richer notes are wanted), and — **only if the `TAP_GITHUB_TOKEN` repo secret
   is configured** — bumps the `chas678/homebrew-jennyj` tap formula
   automatically. See "Homebrew" below.
8. [ ] Verify the install after the tap formula lands:
   ```bash
   brew update && brew upgrade chas678/jennyj/jenny   # or `brew install` first time
   jenny --version   # expect: jenny 1.0.0
   brew test chas678/jennyj/jenny
   ```

### Homebrew distribution

The formula lives in an **external tap repo**, `chas678/homebrew-jennyj` (not in
this repo) — there is nothing to edit here. The `release.yml` workflow's
"Update Homebrew tap formula" step handles a 1.0.0 bump automatically and
end-to-end: it clones the tap, rewrites the formula's `url` (pointing at the
`v1.0.0` release asset), `sha256` (computed from the just-built `jenny.jar`), and
`version` fields, then commits and pushes — **conditional on the
`TAP_GITHUB_TOKEN` secret being set** on this repo (a PAT/fine-grained token with
`contents:write` on the tap repo). If that secret isn't configured yet, the
release step is silently skipped and the tap formula must be bumped by hand
(same three fields) in the tap repo after the GitHub release is published.
**Action needed before/at release time: confirm `TAP_GITHUB_TOKEN` is set in this
repo's secrets**, or plan to do the tap bump manually.
